# XCPC 实时榜单回放程序

一个基于 Python 的 XCPC（ICPC 系程序设计竞赛）实时榜单回放工具。自动读取指定文件夹下 `srk/` 子文件夹中的 `.srk.json` 比赛数据文件，解析出完整的提交时间线，并在网页端以实时榜单的形式还原比赛全程的动态变化，支持播放 / 暂停 / 倍速 / 快进 / 后退 / 拖动进度等时间轴控制。

## 功能特性

- **自动发现数据**：扫描 `srk/` 子文件夹，自动列出全部 `.srk.json` 文件并在页面中选择。
- **完整时间线重建**：从各队伍 `statuses[].solutions[]` 中提取全部提交记录，按毫秒级时间排序生成事件流。
- **标准 ICPC 计分与排名**：过题数降序、罚时升序、并列同名次顺延；罚时 = 通过分钟数 + 20 × 通过前失败提交数（对齐文件内 `sorter` 配置，CE 等不计罚时）。
- **网页实时榜单**：队伍名 / 学校 / 逐题状态（AC / 首杀 / 失败次数 / 待判）/ 过题数 / 罚时 / 排名 / 金·银·铜奖牌，随回放实时刷新。
- **总榜 / 正榜切换**：可切换「总榜」（全部队伍）与「正榜」（仅正式队伍，排除非正式 / 打星队伍）。正榜按正式队伍重新排名并统计奖牌，榜单底部显示队伍构成。
- **时间轴控制**：播放 / 暂停、0.5× ~ MAX 倍速、进度拖动、上一条 / 下一条提交、跳转比赛开始 / 结束、键盘快捷键（空格 / ←→ / ↑↓）。
- **实时动态面板**：最近提交滚动展示，过题高亮、首杀紫色标注。
- **提交活动图**：时间轴上方以直方图呈现每分钟提交密度（绿 = 通过，红 = 失败），带播放头。
- **结果自检**：回放到结束自动与文件内最终榜单比对，页面顶部显示"结果校验通过"徽章。
- **封榜模式**：可开启封榜，封榜窗口内所有提交（无论 AC 还是失败）统一以黄色 "?N" 呈现（N 为该题封榜后的提交次数），且不影响排名与得分。封榜窗口优先取数据中的 `frozenDuration`，未配置时默认封榜最后一个小时。
- **跨平台零依赖**：仅使用 Python 标准库，无第三方依赖、无构建步骤、无 CDN，Windows / macOS / Linux 均可直接运行。

## 环境要求

- Python 3.8 及以上（无任何第三方依赖）

## 快速开始

```bash
# 1. 进入程序目录（确保 srk/ 子文件夹位于当前目录或程序目录下）
cd srk-run

# 2. 启动并自动打开浏览器
python main.py
```

浏览器打开后：选择数据文件 → 点击 ▶ 播放 → 即可观看比赛过程回放。停止服务按 `Ctrl+C`。

其他启动方式：

```bash
python main.py --port 9000          # 指定端口（被占用时自动顺延）
python main.py --srk-dir ./data     # 数据根目录（读取 data/srk/ 下的文件）
python main.py --no-browser         # 不自动打开浏览器
python main.py --quiet              # 关闭访问日志
python main.py --validate           # 只校验数据并退出（不启动服务）
python main.py --version            # 查看版本
python -m xcpc_replay               # 等价于 python main.py
```

## 命令行参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `--host` | `127.0.0.1` | 监听地址 |
| `--port` | `8000` | 起始端口，被占用时自动向后顺延 |
| `--srk-dir` | 当前工作目录 | 数据根目录（读取其下的 `srk/` 子文件夹）；若该目录无 `srk/`，自动回退到程序所在目录 |
| `--no-browser` | 关闭 | 启动后不自动打开浏览器 |
| `--quiet` | 关闭 | 关闭访问日志 |
| `--validate` | 关闭 | 校验模式：解析全部文件并回放，与快照比对后退出 |
| `--version` | 关闭 | 输出版本号 |

## 数据格式说明

程序解析 [XCPCIO SRK](https://github.com/XCPCIO) 榜单快照格式（`.srk.json`）：

| 字段 | 说明 |
|------|------|
| `contest` | 比赛元信息：标题、开始时间、时长、封榜时长 |
| `problems` | 题目列表：别名、通过数 / 提交数 |
| `rows` | 队伍列表：`user`（队名 / 编号 / 学校 / 正式性）、`score`（最终过题数 / 罚时）、`statuses`（每题状态） |
| `rows[].statuses[].solutions` | 该题全部提交记录（判题结果 + 毫秒时间戳）——回放时间线的数据来源；无 `solutions` 的"汇总快照"文件（仅 `result/time/tries`）会自动依据 `tries` 重建提交事件，保证回放与快照罚时一致 |
| `sorter` | 排名规则：罚时单价、不计罚时的结果集合 |
| `series` | 奖项划分：`count`（各段固定人数）与 `ratio`（各段按正式队伍数 × 比例取整，默认向上取整）两种模式，如 `[0.1, 0.2, 0.3]` 表示金 10% / 银 20% / 铜 30%；**各段互不包含**（银不包含金），输出名次累积边界；`noTied` 为真时展开并列名次以保证各段恰好分到规定人数；缺少 ratio 配置时按默认 `[0.1, 0.2, 0.3]` 计算；打星队不计入分母 |

**计分规则**（与文件内 `sorter.config` 对齐）：

- 结果在 `noPenaltyResults` 集合中的提交（如 CE）不计入尝试次数；
- 通过题目：过题数 +1，罚时 += 通过分钟数（向下取整）+ 20 × 通过前失败提交数；
- 未通过题目的失败提交不计罚时；
- 排名按过题数降序、罚时升序，同分并列同名次，后续名次顺延；
- 奖牌只在正式队伍中按名次区间划分（金 / 银 / 铜）。

## 目录结构

```
srk-run/
├── main.py                     # 程序入口
├── srk/                        # 数据文件夹（放 .srk.json 文件，不入库，需自行放置）
│   └── shcpc2026.srk.json      # 演示数据示例（本地已有，未纳入版本控制）
├── xcpc_replay/                # 核心包
│   ├── __init__.py
│   ├── __main__.py             # python -m xcpc_replay 入口
│   ├── cli.py                  # 命令行入口实现
│   ├── parser.py               # 数据解析模块（.srk.json 解析 / 时间线重建）
│   ├── replay.py               # 回放引擎（ICPC 计分 / 排名 / 快照校验 / 载荷组装）
│   ├── server.py               # HTTP 服务（静态资源 + JSON API，零依赖）
│   └── web/                    # 前端资源
│       ├── index.html          # 页面结构
│       ├── style.css           # 深色赛事转播风格样式
│       └── app.js              # 回放状态机与渲染逻辑
└── tests/
    ├── gen_fixture.py          # 合成数据生成器（多种规模 / 边界场景）
    └── test_replay.py          # 单元测试（真实文件 + 合成文件 + API）
```

## API 接口

| 路由 | 说明 |
|------|------|
| `GET /` | 回放主页 |
| `GET /static/*` | 前端静态资源 |
| `GET /api/files` | 可用 `.srk.json` 文件列表 |
| `GET /api/contest?file=<名称>` | 完整回放数据载荷（比赛信息 / 题目 / 队伍 / 事件流 / 最终榜单） |

## 测试

```bash
python main.py --validate                     # 校验 srk/ 下全部真实数据（回放 vs 快照）
python -m unittest discover -s tests -v       # 运行全部单元测试
```

测试覆盖：

- **真实文件（通用化）**：对 `srk/` 目录下**所有** `.srk.json` 自动发现并逐一校验——结构一致性、事件流与提交总数吻合、时间单调、回放结果与文件内最终榜单完全一致、名次顺序吻合、CE 不计尝试/罚时。新增任意 `.srk.json` 无需改测试即自动覆盖；
- **合成数据**：小（12 队 5 题）、中（60 队 10 题）、大（300 队 13 题）、大量同分、空比赛、缺失 `solutions` 等场景；
- **边界与容错**：非法 JSON、缺少必要字段、UTF-8 BOM、`srk/` 目录不存在、文件名目录穿越防护；
- **服务 API**：文件列表、数据载荷、错误处理、页面可访问性。

> 说明：`srk/` 下没有 `.srk.json`（如全新 clone 后未自行放置数据）时，真实文件相关用例自动跳过，其余测试不受影响。

## 跨平台与鲁棒性说明

- 仅依赖 Python 标准库，无第三方包、无 Node 构建链、无 CDN，离线可用；
- 路径处理使用 `os.path` / `pathlib` 兼容三平台分隔符；JSON 以 UTF-8 读取并兼容 BOM；
- 端口被占用时自动顺延；服务为线程化模型，支持并发请求；
- 数据解析全程容错：缺失字段使用保守默认值，单个文件解析失败不影响其他文件；
- 前端无构建、无框架，纯原生 HTML/CSS/JS，主流现代浏览器均可运行。

## 常见问题

- **页面提示"未发现 .srk.json 文件"**：确认数据文件位于 `当前工作目录/srk/` 下，或使用 `--srk-dir` 指定根目录。
- **端口被占用**：程序会自动顺延，请以终端输出的实际地址访问；也可用 `--port` 显式指定。
- **想要更大倍速**：点击 `MAX` 按钮，每帧推进一条提交（全场比赛约几十秒放完）。
